## 객관식 정답과 해설

| 문항 | 정답 | 해설 |
|---|---|---|
| 1 | ② | JSP는 서버의 Jasper/컨테이너에서 처리합니다. |
| 2 | ③ | webapps는 기본 웹 앱 배포 위치입니다. |
| 3 | ④ | name이 요청 매개변수의 키입니다. |
| 4 | ① | String이며 매개변수가 없으면 null입니다. |
| 5 | ① | 읽기 전에 본문 인코딩을 지정합니다. |
| 6 | ② | 이동 응답을 받은 브라우저가 새 요청을 보냅니다. |
| 7 | ③ | session은 여러 요청에 걸쳐 상태를 유지합니다. |
| 8 | ① | invalidate가 현재 세션을 무효화합니다. |
| 9 | ② | POST 자체는 암호화 기능이 없습니다. |
| 10 | ③ | WEB-INF 자원은 직접 HTTP 접근이 차단됩니다. |

## 단답형 예시 답안과 채점

11. `String userId = request.getParameter("userId");` (메서드 5점, 정확한 키·대입 5점)
12. `<%@ page contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" %>` (응답 charset 5점, pageEncoding 5점)
13. 로그인하지 않은 사용자가 URL로 직접 보호된 내용을 보는 일을 막기 위해서입니다. 응답을 커밋하기 전에 이동·종료해야 합니다. (접근 차단 목적 5점, 출력 전 처리 5점)
14. `request.changeSessionId();` 로그인 전 세션 ID를 교체해 세션 고정 공격 위험을 줄입니다. (메서드 5점, 목적 5점)
15. GET은 폼 값이 쿼리 문자열, POST는 요청 본문에 전달됩니다. POST도 본문 자체를 암호화하지 않으므로 HTTPS가 필요합니다. (차이 5점, 기밀성 5점)

동등한 의미와 유효한 Java/JSP 구문은 정답으로 인정합니다. 이 페이지는 학생 자기 점검용 공개 해설입니다. 시험으로 사용할 때는 문제와 해설을 따로 배포합니다.
